# Análise de vulnerabilidades - 2026-10-28

## Comandos executados

```bash
npm audit --omit=dev
npm audit
npm ls prisma @prisma/config deepmerge-ts effect --omit=dev
```

## Resultado das dependências de produção

O comando `npm audit --omit=dev` encontrou 4 vulnerabilidades de severidade alta:

- `deepmerge-ts@7.1.5`: exaustão de pilha ao combinar grafos de objetos recursivos (`GHSA-ggr8-5vv4-36mx`);
- `effect@3.18.4`: perda ou contaminação de contexto `AsyncLocalStorage` em execução concorrente com RPC (`GHSA-38f7-945m-qr2g`).

As duas dependências são transitivas de `@prisma/config@6.19.0`, alcançado por `@prisma/client@6.19.0` e `prisma@6.19.0`. O `npm audit` conta quatro ocorrências altas ao considerar a cadeia de dependências.

## Resultado completo

O comando `npm audit` encontrou 13 vulnerabilidades:

- 9 de severidade baixa, relacionadas principalmente a `deepmerge` na cadeia de ferramentas Jest e Nest CLI;
- 4 de severidade alta, relacionadas a `deepmerge-ts` e `effect` na cadeia do Prisma.

## Decisão

O `npm audit fix --force` não foi executado. A correção sugerida instala `prisma@7.10.1`, uma atualização principal incompatível que exige migração específica do ORM, regeneração do cliente e nova validação completa.

O código da aplicação não importa diretamente `@prisma/config`, `deepmerge-ts` ou `effect`, mas essas dependências permanecem na árvore instalada e o risco não é considerado resolvido. A migração para Prisma 7 deve ser feita em incremento próprio, com build, testes unitários, cobertura, migrations e testes E2E.
