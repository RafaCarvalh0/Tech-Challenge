# Análise de vulnerabilidades - atualizada em 2026-10-29

## Comandos executados

```bash
npm audit --omit=dev
npm audit
npm ls prisma @prisma/config deepmerge-ts effect --omit=dev
```

## Resultado das dependências de produção

O comando `npm audit --omit=dev` encontrou 3 vulnerabilidades de severidade alta:

- `deepmerge-ts@7.1.5`: exaustão de pilha ao combinar grafos de objetos recursivos (`GHSA-ggr8-5vv4-36mx`).

`deepmerge-ts` é uma dependência transitiva de `@prisma/config@6.19.3`, alcançada pela cadeia do Prisma. O `npm audit` conta três ocorrências altas ao considerar essa cadeia. A vulnerabilidade anteriormente registrada em `effect` deixou de ser reportada após a atualização para `effect@3.21.0`.

`prisma` e `@prisma/client` foram alinhados e fixados na versão `6.19.3`.

## Resultado completo

O comando `npm audit` encontrou 12 vulnerabilidades:

- 9 de severidade baixa, relacionadas principalmente a `deepmerge` na cadeia de ferramentas Jest e Nest CLI;
- 3 de severidade alta, relacionadas a `deepmerge-ts` na cadeia do Prisma.

## Decisão

O `npm audit fix --force` não foi executado. A correção sugerida instala `prisma@7.10.1`, uma atualização principal incompatível que exige migração específica do ORM, regeneração do cliente e nova validação completa.

O código da aplicação não importa diretamente `@prisma/config` ou `deepmerge-ts`, mas a dependência permanece na árvore instalada e o risco não é considerado resolvido. A migração para Prisma 7 deve ser feita em incremento próprio, com build, testes unitários, cobertura, migrations e testes E2E.
